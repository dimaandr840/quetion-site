# Картинки вопросов и хранилище Cloudflare R2

Картинки к вопросам загружаются из админки и хранятся не на сервере приложения,
а во внешнем S3-совместимом хранилище. По умолчанию предполагается
**Cloudflare R2**: бесплатный тариф (10 ГБ хранения, без платы за исходящий
трафик) и привычный S3 API.

Функциональность выключена, пока не выставлен `MEDIA_ENABLED=true`. Без него
бэкенд поднимается без S3-клиента, а `POST /api/admin/media` отвечает 503 —
так стенд без хранилища продолжает работать.

## 1. Бакет и токен в Cloudflare

1. Cloudflare Dashboard → **R2** → **Create bucket**. Имя, например, `devprep-media`,
   локация — автоматическая.
2. На странице бакета → **Settings** → **Public access**:
   - либо включите `r2.dev` субдомен (быстро, без своего домена; есть
     ограничения по трафику, для прода не рекомендован),
   - либо привяжите свой домен (**Connect Domain**), например `media.example.com`.
     Это предпочтительный вариант: работает кеш CDN и правила Cloudflare.

   Публичный доступ нужен **только на чтение**. Запись идёт исключительно
   через бэкенд с ключами S3 API, браузер их никогда не видит.
3. R2 → **Manage R2 API Tokens** → **Create API token**:
   - права: **Object Read & Write**,
   - область: только созданный бакет (не вся учётка),
   - сохраните **Access Key ID** и **Secret Access Key** — секрет показывается один раз.
4. Запишите endpoint вида `https://<account_id>.r2.cloudflarestorage.com`
   (Account ID есть на главной странице R2).

## 2. Переменные окружения

Добавьте в `.env` рядом с `docker-compose.yml`:

```env
MEDIA_ENABLED=true
S3_ENDPOINT=https://<account_id>.r2.cloudflarestorage.com
S3_BUCKET=devprep-media
S3_ACCESS_KEY=<access key id>
S3_SECRET_KEY=<secret access key>
S3_REGION=auto

# Публичный адрес, с которого браузер забирает картинки: свой домен или r2.dev.
# Без завершающего слеша.
MEDIA_PUBLIC_BASE_URL=https://media.example.com
```

Дополнительные переменные со значениями по умолчанию:

| Переменная | По умолчанию | Зачем |
| --- | --- | --- |
| `MEDIA_KEY_PREFIX` | `questions` | префикс ключей в бакете |
| `MEDIA_MAX_FILE_SIZE` | `5MB` | лимит одного файла |
| `MEDIA_MAX_REQUEST_SIZE` | `6MB` | лимит всего multipart-запроса |
| `MEDIA_MAX_DIMENSION` | `1600` | большая сторона после уменьшения, пкс |

Фронтенд получает тот же домен через `NEXT_PUBLIC_MEDIA_BASE_URL` — в
`docker-compose.yml` он подставляется из `MEDIA_PUBLIC_BASE_URL` автоматически.
⚠️ Это билд-временная переменная Next.js: после смены домена нужна пересборка:

```bash
docker compose up -d --build web
```

## 3. Как работает загрузка

1. Админ выбирает файл в форме вопроса → `POST /api/admin/media` (multipart, только
   роль `ROLE_ADMIN`, CSRF-токен как и у остальных небезопасных методов).
2. Бэкенд проверяет тип (только JPEG и PNG), **декодирует картинку и кодирует
   заново**, уменьшая большую сторону до `MEDIA_MAX_DIMENSION`. Перекодирование
   важнее экономии места: переименованный в `.jpg` скрипт, полиглот или SVG с
   `<script>` просто не декодируются и получают 400, а EXIF с геолокацией теряется.
3. Объект кладётся в бакет по ключу `questions/<год>/<месяц>/<uuid>.jpg|png` с
   `Cache-Control: public, max-age=31536000, immutable`. Ключ непредсказуем и не
   содержит исходное имя файла.
4. Форма запоминает только ключ и отправляет его вместе с вопросом. Публичный
   URL собирает бэкенд из `MEDIA_PUBLIC_BASE_URL`, поэтому смена домена не требует
   миграции базы.
5. `alt` обязателен и на фронте, и на бэкенде — иначе картинки ломают доступность
   и выдачу в поиске.

## 4. Удаление и сироты

- Картинка, отвязанная от вопроса (или вопрос удалён), удаляется из хранилища
  сразу после успешного сохранения.
- Файл, загруженный и брошенный без сохранения вопроса, остаётся сиротой. Ночной
  `MediaMaintenanceJob` (03:40) удаляет объекты старше суток, на которые нет ссылок
  в таблице `question_image`. Сутки запаса нужны, чтобы чистка не задела файл,
  который админ только что загрузил и ещё не сохранил.

## 5. Лимиты nginx

Глобальный `client_max_body_size` остаётся 2 МБ. Послабление до 6 МБ сделано
точечно в `location = /api/admin/media`. Если вы поднимаете `MEDIA_MAX_FILE_SIZE`,
поднимите и это значение (с запасом на оверхед multipart), иначе админ
увидит 413 от nginx вместо ошибки приложения.

Если картинки отдаются с внешнего домена, добавьте его в `img-src` переменной
`$devprep_csp` в `nginx/nginx.conf` — публичные страницы получают CSP именно
оттуда. Админка и `/login` получают CSP от `frontend/proxy.ts`, который берёт домен из
`NEXT_PUBLIC_MEDIA_BASE_URL` сам.

## 6. Бэкап

Бакет — такой же источник данных, как база: его нужно копировать. Удобнее всего
[rclone](https://rclone.org/s3/#cloudflare-r2):

```bash
# ~/.config/rclone/rclone.conf
# [r2]
# type = s3
# provider = Cloudflare
# access_key_id = ...
# secret_access_key = ...
# endpoint = https://<account_id>.r2.cloudflarestorage.com

rclone sync r2:devprep-media /backup/devprep-media --progress
```

Ставьте это в cron рядом с бэкапом PostgreSQL: база без файлов даст вопросы с
битыми картинками.

## 7. Другие хранилища

Код работает через чистый S3 API и не содержит ничего специфичного для
Сloudflare — поэтому переменные называются `S3_*`, а не `R2_*`. Любой
другой S3-совместимый сервис (Backblaze B2, MinIO, Yandex Object Storage,
любой другой) подключается теми же переменными: достаточно поменять
`S3_ENDPOINT`, `S3_REGION` и ключи.
