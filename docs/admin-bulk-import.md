# Массовая загрузка вопросов через админку

Раздел **Админка → Импорт** (`/admin/import`) принимает файл вопросов того же
формата, что лежит в `scripts/data/*.mjs`, проверяет его и загружает только
корректные вопросы.

## Порядок работы

1. Выбрать файл `.mjs`. Он не сохраняется на диск: содержимое уходит одним
   запросом, разбирается и превращается в JSON.
2. Посмотреть отчёт: сколько вопросов в файле, сколько готово к загрузке,
   сколько с ошибками и что именно не так в каждой строке.
3. Нажать «Загрузить N вопросов». Прогресс и итог показываются на месте,
   ошибки по отдельным вопросам не останавливают остальные.

## Настройки

| Настройка | Что делает |
| --- | --- |
| Публиковать сразу | Снятая галочка загружает всё черновиками (`published: false`) |
| Обновлять существующие | Вопрос с тем же адресом уходит в `PUT` вместо пропуска |
| Создавать отсутствующие темы | Темы из `categories` создаются перед импортом |
| Только тема | Импорт одной темы (по названию или адресу) |
| Лимит вопросов | Пробный прогон на первых N вопросах |

Настройки учитываются при проверке файла, поэтому после их изменения файл нужно
выбрать заново.

## Что считается ошибкой

Правила совпадают с CLI-импортёром (`scripts/import-questions.mjs`), общая
реализация — `frontend/lib/bulk-import.ts`:

- нет заголовка (`t`), темы (`c`) или уровня (`l`);
- уровень не Junior / Middle / Senior;
- нет секций ответа (`s`) или все секции пустые (ни `p`, ни `b`, ни `code`);
- дубликат внутри файла: тот же заголовок в той же теме.

Одинаковые адреса, полученные из разных заголовков, разводятся суффиксом
(`-2`, `-3`), как в CLI-импортёре.

## Как читается файл

Файл вопросов — ES-модуль, но исполнять его не нужно: данные в нём записаны
литералами. `frontend/lib/mjs-data-parser.ts` читает их напрямую — как JSON с
более свободным синтаксисом:

- кавычки любого вида, включая шаблонные строки без подстановок;
- комментарии, висящие запятые, ключи без кавычек;
- склейка длинных строк через `+`;
- ссылки на константы самого файла и разворачивание через `...`.

Всё остальное — вызовы функций, обращения к свойствам (`process.env`),
подстановки `${…}`, незнакомые имена — это ошибка с номером строки. Код из
файла не исполняется ни на сервере, ни в браузере, поэтому испорченный или
вредоносный файл может привести только к отказу разбора.

Разбор делает ручка `POST /admin/import/parse`
(`frontend/app/admin/import/parse/route.ts`); она же ограничивает размер файла
2 МБ, проверяет права у бэкенда по cookie запроса (без прав администратора —
403) и отклоняет запросы с чужого источника по заголовку `Origin`.

В браузере разбор не делается по двум причинам: CSP админки
(`frontend/proxy.ts`) не разрешает ни `blob:` в `script-src`, ни `unsafe-eval`,
а большие файлы дешевле читать на сервере, чем тащить парсер в клиентский бандл.

Проверки разбора покрыты тестами: `frontend/scripts/mjs-data-parser.test.mjs`
(`npm test` в `frontend`).

## Когда лучше CLI

Через админку удобно грузить один файл и сразу видеть отчёт. Для регулярных
прогонов, CI и больших файлов остаётся `scripts/import-questions.mjs` —
см. `docs/import-questions.md`.
