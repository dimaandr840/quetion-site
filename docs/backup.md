# Резервное копирование базы данных

Все данные проекта (вопросы, ответы, пользователи, TOTP-секреты) лежат в
PostgreSQL — в docker-томе `postgres-data`. Индекс Meilisearch производный:
его можно пересобрать из базы, отдельный бэкап ему не нужен.

## Что настроено

| Файл | Назначение |
| --- | --- |
| `scripts/backup-db.sh` | разовый дамп с хоста |
| `scripts/restore-db.sh` | восстановление из дампа |
| `docker-compose.backup.yml` | сервис `db-backup` для автоматических дампов по расписанию |
| `backups/` | каталог с дампами (в git не попадает) |

Формат дампа — `pg_dump -Fc` (custom). Он сжат, из него можно восстановить как
всю базу, так и отдельные таблицы через `pg_restore -t`.

## Автоматические бэкапы

Поднимите стек вместе с overlay-файлом:

```bash
docker compose -f docker-compose.yml -f docker-compose.backup.yml up -d
```

Сервис `db-backup` делает дамп раз в сутки и удаляет файлы старше 14 дней.
Настройки через `.env`:

```env
# Интервал между дампами в секундах (86400 = раз в сутки)
BACKUP_INTERVAL=86400
# Сколько дней хранить дампы (0 — не удалять)
BACKUP_RETENTION_DAYS=14
# Пауза перед первым дампом после старта
BACKUP_INITIAL_DELAY=60
```

Проверить, что бэкапы идут:

```bash
docker compose logs -f db-backup
ls -lh backups/
```

## Разовый бэкап вручную

Перед миграциями и рискованными правками контента:

```bash
./scripts/backup-db.sh
```

Переменные `BACKUP_DIR` и `BACKUP_RETENTION_DAYS` работают и здесь:

```bash
BACKUP_DIR=/mnt/backups BACKUP_RETENTION_DAYS=30 ./scripts/backup-db.sh
```

## Восстановление

```bash
./scripts/restore-db.sh backups/devprep-20260902-030000.dump
```

Скрипт спросит подтверждение, остановит `api` и `web`, восстановит базу в одной
транзакции и снова запустит сервисы. Для неинтерактивного запуска:
`FORCE=true ./scripts/restore-db.sh <dump>`.

После восстановления:

1. `docker compose logs -f api` — убедиться, что миграции прошли и приложение поднялось.
2. Проверить поиск на сайте: бэкенд переиндексирует данные в Meilisearch.
3. Проверить вход в админку.

## Что важно не забыть

- **Копия не должна лежать только на том же сервере.** Настройте выгрузку
  каталога `backups/` во внешнее хранилище (S3/R2, rsync на другой хост).
  Иначе отказ диска убьёт и базу, и бэкапы.
- **Дамп — секрет.** Внутри хеши паролей администраторов и зашифрованные
  TOTP-секреты. Скрипт ставит права `700` на каталог и `600` на файлы; при
  выгрузке наружу используйте приватный бакет и шифрование.
- **Ключи нужны отдельно.** Без `TOTP_ENC_KEY` из `.env` TOTP-секреты из дампа
  не расшифровать, без `JWT_SECRET` — не проверить старые токены. Храните `.env`
  (или сами ключи) в менеджере секретов, а не только на сервере.
- **Проверяйте восстановление.** Раз в квартал разворачивайте свежий дамп в
  тестовом окружении: нерабочий бэкап хуже отсутствующего, потому что на него
  рассчитывают.
- **Картинки живут в объектном хранилище** (R2/S3) и в дамп не входят —
  включите версионирование на бакете, см. `docs/media.md`.
