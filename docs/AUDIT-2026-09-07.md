# Строгий legal / privacy / security / technical audit — 2026-09-07

## Статус

Проверены исходники и публичный адрес. На момент проверки `qareerquest.com` не резолвился в DNS; внешний TLS/HTTP-аудит и подтверждение production-конфигурации поэтому невозможны. Этот документ не является юридическим заключением.

## Критические юридические блокеры

1. Оператор — физическое лицо в РФ, следовательно применим 152-ФЗ. Предыдущая политика ошибочно исходила из того, что одного размещения VPS в Германии достаточно для применения GDPR и отказа от 152-ФЗ.
2. LuxVPS размещает серверы во Франкфурте. Запись, систематизация, накопление, хранение, уточнение и извлечение ПД граждан РФ в базе за пределами РФ противоречат ч. 5 ст. 18 152-ФЗ. До переноса первичной базы в РФ публичный сбор ПД должен быть остановлен.
3. До обработки нужны: уведомление Роскомнадзора по ст. 22; политика и локальные акты; модель угроз/уровень защищённости; назначение ответственного; регламент прав субъектов; уничтожение; журнал инцидентов; договоры поручения обработки. До любой трансграничной передачи — отдельное уведомление по ст. 12 и оценка иностранного получателя.
4. Публичная политика содержит незаполненные реквизиты оператора и ошибочно называет Spaceship хостером. Перед запуском заполнить ФИО, адрес для обращений, email, точные сроки хранения, фактических обработчиков и страны.
5. Google Analytics удалён из активного рендера и CSP. Возвращать иностранную аналитику нельзя без отдельного решения по локализации, трансграничной передаче и доказуемому согласию.

## Исправлено в ветке

- Удалена активная загрузка GA4 и ненужный consent-баннер; CSP больше не разрешает Google.
- Nginx перестал логировать query string, где могли оказаться токены и ПД.
- Юридические страницы больше не зависят от доступности backend API.
- Cookie-страница приведена к фактическому режиму без аналитики.
- Build и runtime backend выровнены на Java 21; добавлен аварийный выход JVM при OOM.
- Подготовлена отдельная ветка и PR; main напрямую не изменяется.

## Высокие остаточные риски

- DNS/NDSSEC: восстановить A/AAAA, проверить отсутствие лишнего AAAA, включить DNSSEC у Spaceship, registrar lock и MFA.
- VPS: перенести первичную БД ПД граждан РФ в российский дата-центр либо исключить сбор таких ПД. Франкфуртский VPS допустим только после отдельного правового анализа и корректной архитектуры трансграничной передачи.
- R2/S3, SMTP, Sentry, GitHub, LuxVPS: составить карту потоков; проверить DPA/поручение, страны и настройки PII. Не включать Sentry/SMTP/R2 для ПД до проверки.
- Политика: заполнить реквизиты владельца. Плейсхолдеры означают запрет production-публикации, а не допустимый текст.
- Логи: установить подтверждённый срок (рекомендация для минимизации — 7–14 дней), доступ по need-to-know, удаление и резервное копирование в РФ.
- Deployment: отказаться от password SSH, root login и mutable action tags; использовать ключ, отдельного deploy-пользователя, protected environment и ручное одобрение production.
- Supply chain: добавить SBOM, подпись образов/attestations, Trivy/Grype, Maven/OSV и проверку лицензий; pin actions по commit SHA.
- Production: провести DAST (TLS, headers, cookies, auth, rate limits), backup restore drill и PostgreSQL concurrency test после восстановления DNS.

## Критерий допуска к запуску

DNS и HTTPS работают; первичная база ПД находится в РФ; уведомления поданы; реквизиты и документы утверждены; трансграничные потоки либо отключены, либо оформлены; секреты ротированы; MFA/SSH-only включены; CI и staging проверки зелёные; восстановление бэкапа проверено.
