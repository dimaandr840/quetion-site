# Импорт вопросов через админский API

Скрипт `scripts/import-questions.mjs` заливает вопросы пачкой: он ходит в те же
ручки `/api/admin/**`, что и админка, поэтому не нужно ни писать в базу руками,
ни держать отдельный формат сида.

## Как это работает

1. `GET /api/auth/csrf` — получает cookie `XSRF-TOKEN`.
2. `POST /api/auth/login` — вход по паролю. Если включена 2FA
   (`TOTP_REQUIRED_FOR_ADMINS=true`), ответ приходит со статусом `TOTP_REQUIRED`.
3. `POST /api/auth/totp/verify` — код из аутентификатора. Скрипт считает его сам
   из base32-секрета тем же алгоритмом, что `scripts/totp-code.cjs`.
4. `GET /api/categories?profession=...` и `POST /api/admin/categories` —
   создаются только отсутствующие темы.
5. `GET /api/admin/questions` — снимок того, что уже есть; по нему решается,
   создавать вопрос (`POST`) или обновлять (`PUT /api/admin/questions/{slug}`).

Токены остаются в httpOnly cookie: скрипт их не читает и никуда не печатает.

## Запуск

Сначала холостой прогон — он ничего не пишет и не требует доступа к API:

```bash
node scripts/import-questions.mjs data/qa.mjs --dry
```

Затем импорт:

```bash
DEVPREP_API=http://localhost/api \
ADMIN_EMAIL=admin@example.com \
ADMIN_PASSWORD='...' \
ADMIN_TOTP_SECRET='BASE32SECRET' \
  node scripts/import-questions.mjs data/qa.mjs
```

Если секрет держать в окружении нельзя, передайте разовый код:
`ADMIN_TOTP_CODE=123456` (живёт 30 секунд).

| Флаг | Что делает |
| --- | --- |
| `--dry` | только проверка файла и статистика, без запросов к API |
| `--update` | обновлять существующие вопросы (по умолчанию они пропускаются) |
| `--draft` | импортировать как черновики (`published=false`) |
| `--only=<тема>` | взять вопросы одной темы, флаг можно повторять |
| `--limit=<N>` | залить не больше N вопросов — удобно для первой пробы |

| Переменная | Зачем |
| --- | --- |
| `DEVPREP_API` | база API, по умолчанию `http://localhost/api` |
| `ADMIN_EMAIL`, `ADMIN_PASSWORD` | учётка администратора |
| `ADMIN_TOTP_SECRET` | base32-секрет аутентификатора |
| `ADMIN_TOTP_CODE` | готовый 6-значный код вместо секрета |

## Формат файла данных

Файлы лежат в `scripts/data/*.mjs` и экспортируют объект по умолчанию:

```js
export default {
  professionSlug: "qa-engineer",
  categories: [
    { slug: "testing-basics", title: "Основы тестирования", emoji: "🧪" },
  ],
  questions: [
    {
      t: "Чем отличается smoke от regression?",
      l: "Middle",                 // Junior | Middle | Senior
      c: "testing-basics",         // slug темы из categories
      g: ["тест-дизайн"],          // теги
      d: "Короткий TL;DR",
      pop: false,
      s: [
        {
          h: "Определение",
          p: ["Абзац с <strong>разметкой</strong>."],
          b: ["пункт списка"],
          code: { lang: "bash", title: "Пример", lines: ["pytest -m smoke"] },
        },
      ],
    },
  ],
};
```

Скрипт сам собирает то, что не нужно писать руками: `slug` (транслит заголовка с
суффиксом при совпадении), `snippet` и `tldr` (из `d`, иначе из текста ответа).

В инлайн-разметке допустимы `<strong>`, `<em>`, `<code>`, `<mark>`, `<u>`, `<s>`,
`<a href>`. В `snippet`, `tldr` и поисковый индекс теги не попадают.

Абзацы уходят в API как `sections[].blocks[{ kind: "PARAGRAPH", text }]` — это
единственное поле с текстом, которое читает бэкенд (`AnswerSectionDto`).
Картинки в ответах импортом не поддерживаются: файл нужно сначала загрузить
через медиа-ручку, поэтому их добавляют в админке.

## Проверки и повторные запуски

- Файл валидируется до первого запроса: незнакомый уровень, отсутствующая тема,
  пустая секция или вопрос без заголовка останавливают импорт целиком.
- Дубликаты внутри файла (тема + заголовок) отбрасываются с предупреждением.
- Повторный запуск без `--update` не создаёт копий: вопрос с таким заголовком
  пропускается. С `--update` он перезаписывается по своему `slug`.
- `429` и `5xx` повторяются трижды с паузой; при непустом списке ошибок скрипт
  завершается кодом 1, поэтому его можно ставить в CI.

После импорта счётчики профессии и тем пересчитываются бэкендом, а
опубликованные вопросы переиндексируются в Meilisearch.
