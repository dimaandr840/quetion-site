# Соответствие 152-ФЗ: статус и пробелы

Рабочий чек-лист по переводу проекта под российский режим обработки
персональных данных. Обновляйте статусы прямо здесь.

> Не является юридическим заключением. Формулировки политик, уведомление в РКН
> и внутренние приказы согласуйте с юристом.

## Ключевое расхождение

Юридический контур сайта сейчас построен под GDPR: страницы
`frontend/app/(public)/legal/privacy` и `.../cookies` прямо ссылаются на
ст. 6, 13, 32 GDPR и § 25 TDDDG, потому что VPS находится в Германии.
Переход на 152-ФЗ невозможен без переноса инфраструктуры: политика под 152-ФЗ
при базе в ЕС будет недостоверной.

**Порядок действий: сначала миграция инфраструктуры в РФ, затем переписывание
политик, затем уведомление в РКН.** Обратный порядок создаёт риск сам по себе.

## 1. Документы на сайте

| Требование | Статус | Где |
| --- | --- | --- |
| Политика обработки ПДн в свободном доступе (ст. 18.1) | Есть страница, но текст под GDPR и с незаполненными плейсхолдерами | `frontend/app/(public)/legal/privacy/page.tsx` |
| Пользовательское соглашение отдельным документом | Добавлено (шаблон) | `frontend/app/(public)/legal/terms/page.tsx` |
| Политика cookie отдельной страницей | Есть, текст под TDDDG | `frontend/app/(public)/legal/cookies/page.tsx` |
| Ссылки доступны с любой страницы | Есть | `frontend/components/layout/Footer.tsx` |
| Отдельный непреотмеченный чекбокс согласия на ПДн | Не применимо сейчас: публичной регистрации нет (`REGISTRATION_ENABLED=false`, `/api/auth/register` доступен только вошедшему админу) | `backend/.../web/AuthController.java` |

## 2. Cookie-баннер

| Требование | Статус |
| --- | --- |
| Баннер при первом визите с описанием категорий | Есть |
| Равнозначные «Принять все» / «Только необходимые», без предвыбора | Есть |
| Ссылка на политику cookie из баннера | Есть |
| Отзыв согласия в один клик | Есть, `CookieSettingsButton` в подвале |
| Аналитика не грузится до согласия | Есть, `components/analytics/GoogleAnalytics.tsx` |
| Серверный журнал согласий (факт, дата, IP) | **Нет.** Решение хранится только в cookie `dp_cookie_consent` в браузере |

Google Analytics при переходе на 152-ФЗ — трансграничная передача в США.
Либо уведомлять РКН отдельно, либо заменить на Яндекс Метрику или
self-hosted-аналитику.

## 3. Локализация данных (с 01.07.2025)

| Компонент | Сейчас | Что нужно |
| --- | --- | --- |
| PostgreSQL | VPS Spaceship, Германия | Перенести на сервер в РФ |
| Объектное хранилище | `MEDIA_ENABLED=false`, `S3_ENDPOINT` пуст; в README упомянут Cloudflare R2 | При включении медиа использовать российское хранилище (Yandex Object Storage, VK Cloud, Selectel) |
| Бэкапы | `BACKUP_S3_*` пусты | Хранить копии в РФ; шифрование `BACKUP_CIPHER_PASS` обязательно |
| SMTP | `SMTP_HOST` пуст | Российский провайдер, иначе — уведомление о трансграничной передаче |
| Аналитика | GA4 | См. выше |
| Мониторинг | Self-hosted Grafana/Prometheus/Loki/Tempo, `SENTRY_DSN` пуст | Оставить self-hosted; облачный Sentry = трансграничная передача |

## 5. Права субъекта данных

| Требование | Статус |
| --- | --- |
| Канал обращений | Есть: почта в политике и подвале |
| Удаление данных по запросу | **Нет автоматизированного механизма.** Учётные записи создаёт и удаляет администратор вручную; эндпоинта удаления/выгрузки нет |
| Отзыв согласия на cookie | Есть |
| Срок ответа на обращение | Не зафиксирован в документах |

## 6. Безопасность — что уже сделано

- JWT только в httpOnly-cookie, `COOKIE_SECURE`, `COOKIE_SAME_SITE=Strict`
- Обязательный TOTP для администраторов, шифрование секрета AES-GCM
- Anti-replay для TOTP, блокировка перебора, rate limit на вход
- Пароли — хеши; смена пароля гасит все сессии
- CSRF-токен, заголовки безопасности и CSP
- Шифрованные бэкапы с проверкой восстановления
- Логи с `requestId` и `userId`, алерты в Alertmanager
