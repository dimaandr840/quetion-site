# UI/UX-аудит DevPrep и переработка фильтра

Аудит выполнен по трём наборам принципов: **Taste Skill** (вкус: иерархия,
сдержанность, отсутствие декора без задачи), **UI UX Pro Max Skill** (сценарии,
обратная связь, состояния, доступность) и **Impeccable** (аккуратность деталей:
сетка, радиусы, попадания, отсутствие «почти правильных» значений).

Главный вывод: сайт хорошо написан технически (server components, URL как
состояние, честные токены), но **список вопросов работал как форма, а не как
инструмент подбора**. Основная переработка сделана именно там.

---

## 1. Что было не так с фильтром (14 находок)

### Взаимодействие

1. **Отложенное применение.** Фильтр был GET-формой с кнопкой «Применить»:
   выбор уровня ничего не менял, пока пользователь не нажмёт кнопку. Это два
   действия там, где должно быть одно, и нулевая обратная связь между ними.
2. **Нет счётчиков.** Ни у уровня, ни у профессии не было числа результатов.
   Пользователь выбирал «наугад» и узнавал результат только после отправки.
   В CSS даже был неиспользуемый класс `.optionCount` — задачу понимали, но не
   довели.
3. **Нельзя было снять один фильтр.** Не было ни сводки активных условий, ни
   чипсов, ни очистки отдельной группы. Только общая ссылка «Сбросить» с низкой
   заметностью.
4. **Тупики.** Значения с нулём результатов оставались активными: клик вёл к
   пустому экрану без объяснения причины.
5. **Результат жил отдельно от фильтра.** Количество найденного показывалось в
   тулбаре и никак не связывалось с только что сделанным выбором.
6. **`page` терялся неявно.** Смена фильтра на 5-й странице приводила к
   непредсказуемому состоянию пагинации.

### Структура

7. **Сортировка лежала внутри фильтра.** Это разные задачи: фильтр сужает
   выборку, сортировка меняет порядок. Смешение делало панель «списком всего,
   что можно настроить».
8. **Неограниченный список профессий.** Плоский набор чекбоксов без поиска и
   без «показать ещё» — при росте контента панель растёт бесконечно. Это
   нарушало собственное правило проекта из `DESIGN-NOTES.md`: «длинный список —
   причина сменить компонент, а не сделать его длиннее».
9. **Две разные модели для одной задачи.** Страница темы фильтровала уровни
   пилюлями + нативным `select`, остальные три страницы — сайдбаром с
   чекбоксами. Один сценарий выглядел как два разных продукта.

### Мобильные и доступность

10. **На узком экране панель становилась стеной.** До 1000px сайдбар
    складывался *над* результатами: чтобы дойти до первого вопроса, надо было
    проскроллить весь фильтр. Ни шита, ни сворачивания не было.
11. **Цели касания меньше нормы.** Чекбоксы 14×14 в строках 36px и нативный
    `select` высотой 33px — при собственном правиле проекта «минимум 44px».
12. **Системный вид контролов.** Чекбоксы рисовались через `accent-color`, то
    есть в тёмной теме и в разных браузерах выглядели по-разному.

### Детали (Impeccable)

13. **Нарушение собственного «shape lock».** `list.module.css` использовал
    `--radius-12` и `--radius-6`, хотя проект зафиксировал
    `--radius-control: 10px` / `--radius-surface: 14px` / `--radius-shell: 20px`.
    Панель и карточки рядом имели чуть разные радиусы — глаз это ловит.
14. **Отсутствие иерархии внутри панели.** Ни разделителей, ни группировки, ни
    подписей-микротипографики: «сырой» HTML-вид формы.

## 2. Что сделано: фильтр как «фасетная консоль»

### Мгновенное применение

Клик по значению сразу меняет URL и выдачу (`useRouter` + `useTransition`,
`scroll: false`). Кнопка «Применить» осталась только внутри `<noscript>` —
без JS страница по-прежнему работает как обычная GET-форма. Любое изменение
фильтра сбрасывает `page`, потому что страница 5 старой выборки бессмысленна.

URL остаётся единственным источником состояния: ссылку на выборку можно
отправить коллеге. Значения по умолчанию (`sort=popular`) в URL не пишутся,
чтобы не плодить дубли одного и того же экрана.

### Фасетные счётчики

`lib/facets.ts` считает количество результатов для каждого значения **до**
клика. Счётчик группы игнорирует собственный выбор этой группы — иначе после
выбора «Middle» у Junior всегда был бы 0, и фильтр перестал бы отвечать на
вопрос «а что если переключиться». Значения с нулём результатов выключены:
тупиков больше нет.

Счётчики и выдача считаются одним и тем же кодом (`applyQuestionFilters`), так
что панель физически не может обещать больше, чем покажет список.

### Сложность — сегменты, а не чекбоксы

Три значения с уже существующим цветовым кодом (`Junior` — зелёный,
`Middle` — жёлтый, `Senior` — красный, как в `LevelBadge`) стали плитками
56px с точкой, названием, счётчиком и галочкой в углу. Цвет не единственный
носитель смысла — рядом всегда есть текст.

### Профессия — управляемый список

Поиск внутри группы (появляется от 8 значений), первые 6 значений + «Показать
ещё N», выбранное никогда не прячется под свёрткой, счётчик у каждой строки,
свой бокс 18px вместо системного чекбокса, строка 40px с полем нажатия во всю
ширину.

### Сортировка ушла в тулбар результатов

Сегментный контрол «Популярные / Сложность / А–Я» рядом с количеством
найденного. Нативный `select` убран. В `SORT_OPTIONS` добавлено короткое
название `short`, чтобы подпись влезала в сегмент, а полное осталось в `title`.

### Активные фильтры — чипсы над выдачей

Каждое условие снимается по клику, есть «Сбросить всё». Чипсы стоят рядом с
результатами, а не внутри панели, потому что на мобильном панель закрыта.

### Мобильный шит

До 1000px панель превращается в нижний шит по кнопке «Фильтры · N»:
затемнение, ручка, крестик, закрытие по Escape с возвратом фокуса, блокировка
скролла body, CTA «Показать N вопросов». Это **тот же DOM**, переключаемый
CSS, — не вторая реализация, которая разъедется с первой.

### Один язык на всех экранах

Страница темы больше не использует пилюли + `select`. Она получила
`LevelPicker` — те же плитки, те же счётчики, те же цвета, только в инлайн-
раскладке, плюс общий `ResultsToolbar`. Четыре страницы (`/questions`,
`/professions/[slug]`, `/professions/[slug]/[category]`, `/search`) теперь
говорят одинаково.

### Детали

- Все радиусы приведены к зафиксированным токенам.
- Цели касания: плитки 56px, строки 40px с полным hit-area, тумблер и кнопки
  шита — 44–48px.
- Состояние загрузки: спиннер в подвале панели и `aria-busy` на время
  перехода, вместо «ничего не происходит».
- `aria-pressed` на всех переключателях, `legend` у групп, `aria-live` на
  строке результата, отдельные `aria-label` у кнопок снятия чипса.
- Уважается `prefers-reduced-motion`.

## 3. Прочие замечания по сайту (не фильтр)

Эти пункты в текущей правке не менялись, но их стоит закрыть следующими:

1. **Поиск и фильтр визуально одного веса.** Стоит явнее развести «найти» и
   «сузить»: поиск — основное поле страницы, фильтр — вторичный инструмент.
2. **Пустые состояния.** Сейчас они текстовые; полезнее предлагать конкретное
   следующее действие («снять уровень», «убрать профессию») по данным фасетов.
3. **Страница профессии перегружена по вертикали:** специализации, «другие
   темы» и список вопросов идут одним потоком без якорной навигации.
4. **Аккордеон на странице темы** открывает первый вопрос по умолчанию — это
   спорно при глубокой пагинации, потому что сдвигает позицию контента.
5. **Скелетоны.** При мгновенном фильтре стоит добавить скелетон-строки на
   время `isPending`, а не только спиннер в панели.

## 4. Как проверялось

Собрать Next.js в песочнице нельзя (нет установки зависимостей), поэтому
разметка и **неизменённые** CSS-модули были прогнаны через статический
прототип и отсняты в трёх состояниях: светлая тема (1440px), тёмная тема
(1440px) и мобильный шит (390px). По результатам просмотра исправлены две
реальные ошибки: контролы шита протекали в десктопную вёрстку и галочка
перекрывала подпись уровня.
