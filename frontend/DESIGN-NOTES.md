# DESIGN NOTES — слой 2 (заимствования из taste-skill и ui-ux-pro-max-skill)

Документ фиксирует, что именно взято из двух референсных скиллов, как это
применено в DevPrep и какие правила теперь обязательны для новых экранов.

## Дилы проекта

| Дил | Значение | Что это значит на практике |
| --- | --- | --- |
| DESIGN_VARIANCE | 7 / 10 | Смелая композиция и характерные детали, но без разрушения существующей системы токенов |
| MOTION | 5 / 10 | Движение только там, где оно объясняет структуру: вход заголовка, колода карточек, hover-подсветка |
| DENSITY | 5 / 10 | Спокойные отступы, длинные списки уходят в горизонтальный rail |

## Взято из `Leonxlnx/taste-skill`

1. **Асимметричный сплит вместо центрированного героя.** Главная больше не
   «заголовок по центру над двумя плавающими градиентными пятнами». Слева —
   текст и действия, справа — колода реальных карточек.
2. **Дисциплина текста в герое: ровно 4 элемента.** Надзаголовок, H1, лид,
   поиск + действия. Цифры и теги вынесены в отдельную полосу ниже.
3. **Лид не длиннее 20 слов** (`lib/content.ts` → `HERO.subtitle`).
4. **Kinetic typography по словам.** `components/ui/KineticTitle.tsx` +
   `.kinetic-word` в `styles/motion.css`. Задержка через `--word-index`, JS в
   рантайме не участвует.
5. **EMPHASIS RULE.** Акцент в заголовке — маркер того же шрифтового
   семейства (`.kinetic-accent::after`), а не второй шрифт и не градиентный
   текст с потерей контраста.
6. **Motion must be motivated.** Бесконечный градиентный пан заменён на
   одноразовый `.shine-once`; плавающие блобы убраны; sweep-блик на кнопке
   оставлен только для главного действия.
7. **Никаких фейковых скриншотов.** Правый блок героя собран из того же
   `QuestionCard`, что работает в каталоге, — если компонент изменится,
   изменится и превью.
8. **SHAPE CONSISTENCY LOCK.** Три радиуса и одно правило:
   - интерактивное (кнопки, инпуты, пилюли) → `--radius-control` (10px)
   - поверхности (карточки, панели) → `--radius-surface` (14px)
   - крупные композиционные блоки → `--radius-shell` (20px)
   Смешивать другие значения нельзя.
9. **Тонированные тени.** `--shadow-*` строятся на `--shadow-tint`, тени
   больше не чёрные; `--shadow-accent` — только для главного действия.
10. **Длинный список — причина сменить компонент.** Стена пилюль тем
    превращена в `.rail` со `scroll-snap` и мягкими краями.
11. **Непрерывные значения указателя — не в состоянии React.**
    `SpotlightScope.tsx` пишет `--mx/--my` через `requestAnimationFrame`
    напрямую в DOM-узел, без `useState`.

## Взято из `nextlevelbuilder/ui-ux-pro-max-skill`

1. **Fluid type scale.** `--step-display/h1/h2/h3/h4/lead` на `clamp()`;
   лестница `@media` для размеров шрифта удалена.
2. **Стекло с честным фолбэком.** `--glass-*` + `.glass`; при
   `prefers-reduced-transparency: reduce` поверхности становятся плотными.
3. **Чек-лист перед сдачей** (см. ниже) — контраст, фокус, reduced-motion,
   проверка на 375 / 768 / 1024 / 1440.
4. **Тёмная тема — не инверсия.** Все новые токены (тени, стекло, свечение,
   сетка) переопределены в `[data-theme="dark"]` отдельными значениями.

## Чек-лист перед сдачей нового экрана

- [ ] Контраст текста ≥ 4.5:1, крупного текста ≥ 3:1 (WCAG AA) в светлой и тёмной теме
- [ ] Видимый `:focus-visible` у всех интерактивных элементов
- [ ] Тач-таргеты ≥ 44×44px
- [ ] Проверено на 375 / 768 / 1024 / 1440px — нет переполнений и наложений
- [ ] `prefers-reduced-motion: reduce` — layout не ломается, анимации выключены
- [ ] `prefers-reduced-transparency: reduce` — стекло становится плотным
- [ ] Радиусы взяты только из трёх токенов (SHAPE CONSISTENCY LOCK)
- [ ] Нет бесконечных анимаций, кроме максимум одного `marquee` на страницу
- [ ] Нет фейковых «скриншотов продукта» из div-ов
- [ ] Непрерывные значения указателя/скролла не лежат в состоянии React

## Фильтр (переработан)

Разбор и обоснование — в `UX-AUDIT.md`. Правила, которые нельзя ломать:

1. **Фильтр применяется мгновенно.** Кнопка «Применить» допустима только
   внутри `<noscript>`.
2. **У каждого значения есть счётчик**, и он считается тем же кодом, что
   выдача (`lib/facets.ts`). Счётчик группы игнорирует выбор внутри себя.
3. **Нулевые значения выключены** (`disabled`), если не выбраны сейчас.
4. **Сортировка — не фильтр.** Она живёт в `ResultsToolbar` рядом с
   результатом и никогда не внутри панели фильтров.
5. **Состояние — в URL.** Ссылки собираются только через `buildListHref`
   (`lib/list-url.ts`). Дефолты в URL не пишутся, `page` сбрасывается при любом
   изменении выборки.
6. **Активные условия снимаются по-одному** чипсами над выдачей.
7. **Длинный список — причина сменить компонент.** От 8 значений — поиск
   внутри группы, видимых по умолчанию — 6 + «Показать ещё N». Выбранное не
   прячется под свёрткой никогда.
8. **До 1000px панель — шит**, а не блок над результатами. Шит и десктопная
   панель — один и тот же DOM, переключаемый CSS. Вторую верстку для мобильных
   не создавать.
9. **Один язык на всех списковых страницах.** Нельзя вводить отдельный
   вариант фильтра для одной страницы: либо `QuestionFilters`, либо
   `LevelPicker` с теми же классами из `Filters.module.css`.
10. **Цели касания:** плитка уровня — ≥ 56px, строка списка — ≥ 40px с
    нажимом по всей ширине, тумблер и кнопки шита — ≥ 44px. Нативные
    `select`/`checkbox` в фильтрах больше не используются.
11. **SHAPE CONSISTENCY LOCK действует и в фильтре:** только
    `--radius-control` / `--radius-surface` / `--radius-shell` / `--radius-pill`.
